# Модернизация приложения

## Объём и исходная точка

Выполнено только задание № 3 из `HOMEWORK.md`. Задание № 4 не выполнялось. `ANALYSIS.md` сохранён как описание исходного состояния приложения; он не переписывался под новую реализацию.

До изменений сверены исходники, миграции, зависимости и доступное локальное окружение. Для работы использованы CPython 3.12.15 и uv 0.13.5; в репозитории создано локальное `.venv`, а чистая установка проверена в отдельном venv. Синтаксис 44 Python-файлов приложения и 91 файла vendored SDK (всего 135) проверен через `ast.parse` без исполнения. Docker не установлен; локальный Redis не принимал соединения на `127.0.0.1:6379`.

## Обнаруженные проблемы и изменения

### Зависимости и конфигурация

- Зависимости исходного проекта были старыми и не задавали воспроизводимого окружения для используемого Python. Добавлены диапазоны прямых зависимостей в `pyproject.toml`, разрешённые версии и источники зафиксированы в `uv.lock`, а `requirements.txt` экспортирован с версиями и hash.
- Выбор PostgreSQL был жёстко задан и мешал запуску в окружении без сервера БД. SQLite теперь используется по умолчанию; PostgreSQL сохраняется как конфигурируемый вариант. В этом проекте миграции реально применены к SQLite, PostgreSQL не проверялся.
- Параметры окружения и секреты вынесены в `.env`; добавлен `.env.example` без реальных секретов. Небезопасный секрет допустим только при локальном `DEBUG`; при `DEBUG=false` отсутствие `DJANGO_SECRET_KEY` вызывает явную ошибку конфигурации.
- Настройки Celery и периодический запуск задачи вынесены в код конфигурации, который использует переменную broker. Интервал плановой задачи составляет пять минут. Поскольку Redis-сервер недоступен, подключение worker и Beat не проверено.
- Синхронные unary gRPC-вызовы Tinkoff теперь получают deadline через client interceptor. Настройка `TINKOFF_RPC_TIMEOUT_SECONDS` по умолчанию равна 10 секундам и обязана быть положительным конечным числом. Умышленно более короткий timeout конкретного вызова сохраняется; более длинный ограничивается этим значением. Deadline применяется к отдельному RPC, а не задаёт общий лимит на весь многостраничный запрос свечей.

### Исправления реализации и связанные регрессионные тесты

- Исправлен префикс включения URL пользователя: до этого маршруты склеивались без `/`, из-за чего ожидаемые `/user/login/` и `/user/registration/` не открывались.
- Регистрация и вход валидируют формы до обращения к данным, нормализуют email одинаково (обрезают пробелы и приводят к нижнему регистру), показывают ошибки формы и используют проверку пароля Django. Это устраняет расхождение регистра между созданием аккаунта и входом.
- Выход выполняется POST-запросом с CSRF-токеном, а не изменяющим состояние GET-запросом.
- Запись через REST API теперь требует аутентификации (`IsAuthenticatedOrReadOnly`); публичное чтение сохранено. Поле `uid` включено в сериализацию. Для отсутствующего объекта возвращается 404.
- Исправлена загрузка справочника: повторный импорт теперь обновляет существующую акцию по уникальному `figi`, а не пытается создать дубликат при изменении атрибутов инструмента.
- Обработка ошибок рыночного API централизована в `MarketDataError`: отсутствие токена, пустой ответ, отсутствие истории и сбой провайдера сообщаются явно; в журнал записываются ошибки внешнего сервиса. Значения цены и свечей учитывают дробную часть `nano`. При первом обновлении тренд остаётся неизвестным; равная цена не считается ростом. Обновление сохраняет цену и время получения.
- Истечение RPC deadline (`DEADLINE_EXCEEDED`) отдельно распознаётся для запроса цены, свечей и каталога; пользователю/команде возвращается сообщение с фактическим заданным интервалом ожидания. Проверка выполнялась с mock transport и подменёнными ответами SDK, без вызова живого Tinkoff API.
- Представление деталей использует штатную обработку отсутствующей акции Django и возвращает 404, вместо ошибки при обращении к отсутствующему объекту.
- График использует версию Plotly.js, соответствующую зафиксированному пакету Plotly, а не подвижный URL `plotly-latest`. URL этой библиотеки по-прежнему требует доступности CDN браузеру.

Локальная упаковка удаляет недоступную зависимость, задаёт описание пакета и путь к копии upstream README; диапазоны Python и прочих runtime dependencies сохранены в эквивалентном виде. Это packaging correction; отсутствие отдельного PyPI distribution само по себе не трактуется как доказательство неработоспособности SDK-клиента. Полный URL источника, commit, лицензия и изменения metadata записаны в `vendor/tinkoff-investments/UPSTREAM.md`.

SDK теперь является прямой локальной зависимостью в `pyproject.toml`, пакет и его транзитивные зависимости входят в `uv.lock`, а `requirements.txt` ссылается на `./vendor/tinkoff-investments`. `uv sync --frozen` устанавливает и повторно сохраняет SDK без дополнительного `--no-deps` шага. Валидация чистого окружения и `uv pip check` проведены после изменения упаковки; результаты ниже.

## Проверенные функции

Сохранность исходных пользовательских сценариев сверена с требованиями и поведением, описанным в `ANALYSIS.md`.

- Регистрация, вход и выход: URL, нормализация email, создание и проверка пароля, ошибки некорректного ввода и дублирующегося адреса, отсутствие входа с неверным паролем, POST-выход с CSRF — покрыты тестами. HTTP-сессия регистрации, входа и выхода также проверена на запущенном сервере.
- HTML-список и карточка акции, создание, редактирование и удаление: тесты проверяют отображение, требование входа, валидацию формы и сохранение изменений. HTTP CRUD выполнен на сервере.
- REST API: проверены публичное чтение, аутентификация записи, list/detail/create/patch/delete, валидация данных, фильтрация, поиск, сортировка, `uid` и 404 для отсутствующей акции. HTTP-запросы этих типов также отправлены серверу.
- Обновление котировки: тест проверяет дробную часть цены, изменение цены, тренд и `updated_at`; повторный импорт проверяет обновление существующей акции по `figi`.
- Пароли: тесты проверяют вход только с точным паролем с граничными пробелами, сохранение пароля регистрации без обрезания и отклонение пары значений, отличающихся только пробелами. Нормализация email остаётся проверенной.
- Deadline и transport: mock continuation перехватчика проверяет конечное значение timeout, фактически переданное transport, а также сохранение меньшего timeout. Отдельные тесты моделируют `DEADLINE_EXCEEDED` от методов цены, свечей и каталога, проверяя понятную ошибку с настроенным интервалом.
- SDK и protobuf: smoke test импортирует настоящий upstream SDK из локально установленного пакета, сериализует запрос в Protobuf и разбирает его обратно установленной версией protobuf. Это не выполняет сетевой RPC.
- График: тест с подменёнными свечами проверяет передаваемую в построение цену с `nano` и конфигурацию Plotly. Это проверка кода построения, не получение настоящих котировок.
- Отсутствующий Tinkoff-токен: проверен тестом и на HTTP-странице детали — приложение явно сообщает о необходимости `TINKOFF_TOKEN`, не подставляя демонстрационную цену.
- Неизвестная акция: для REST API фактически получен HTTP 404; HTML-представление и тесты также проверяют 404.
- Ошибки и неправильный ввод: проверены тестами форм, API и ошибок провайдера; это не заменяет проверку каждого возможного сбоя внешней сети.

В тестах Tinkoff-клиент и свечи подменяются. Мок-данные подтверждают только обработку ответов и поведение локального кода.

## Непроверенное и оставшиеся ограничения

- **Tinkoff:** действующего токена не предоставлено; живые вызовы, импорт реального справочника, котировки и соответствие данных рынку не проверялись. Регрессии клиента и deadline используют только mock transport / подменённые ответы. SDK архивирован; локальная упаковка согласует его runtime metadata с lock-файлом.
- **Redis/Celery:** Python-клиент Redis установлен, но локальный Redis-сервер отсутствует (TCP-подключение к `127.0.0.1:6379` отклонено). Worker, Beat, брокер и фактическое фоновое выполнение не запускались. Периодичность и функция задачи проверялись статически и тестами.
- **PostgreSQL:** конфигурация сохранена, однако сервер и credentials для проверки подключения не предоставлены; проверена только SQLite.
- **Python:** локально проверен только Python 3.12.15. Python 3.13 и 3.14 не запускались.
- **Браузер и внешние ресурсы:** HTTP-ответы проверены, полноценный браузерный рендеринг и доступность внешних CDN не проверялись. График использует версионированный Plotly CDN и требует его доступности в браузере.
